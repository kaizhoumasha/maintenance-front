# 管理端前端设计

日期：2026-11-21

本规格描述 `maintenance-front` 的第一版管理端。它对接 `maintenance-admin` 已有的认证、菜单、工作线、设备、用户、角色、权限、菜单和审计接口。列表分页以统一的 `start` / `end` 行号窗口为准，后端合同见 [maintenance-admin#137](https://github.com/kaizhoumasha/maintenance-admin/issues/137)。

## 1. 目的

现场管理员在一个应用里完成配置：工作线、设备、用户与授权、菜单，以及审计查阅。页面按后端种子菜单的 `component` 路径落地，按钮按当前用户的权限码显示。

## 2. 范围

本轮页面：

| 路径 | 页面 | 数据 |
|---|---|---|
| `/asset/device` | 设备管理 | `start` / `end` |
| `/asset/workline` | 工作线管理 | `start` / `end` |
| `/system/user` | 用户管理 | `start` / `end` |
| `/system/user/:id` | 用户详情 | 单条 |
| `/system/role` | 角色管理 | 一次取全量 |
| `/system/permission` | 权限管理 | 一次取全量 |
| `/system/menu` | 菜单管理 | 一次取整棵树 |
| `/system/audit-log` | 审计日志 | `start` / `end` |

对接历史页面和 ECS 调试台不在本轮。对接历史的列表接口仍随 #137 改为 `start` / `end`，避免后端保留第二种列表分页。

## 3. 技术栈与运行方式

独立应用，不并入 `wes_frontend`。包管理使用 pnpm。

| 层 | 选择 |
|---|---|
| 框架 | Vue 3、Vite、TypeScript |
| 路由 | Vue Router 5 |
| 样式与组件 | Tailwind CSS v4、shadcn-vue（Reka UI）、lucide-vue-next |
| 界面状态 | Pinia：访问令牌、当前用户权限码、侧栏收起 |
| 服务端数据 | TanStack Query |
| 表格 | TanStack Table，经 shadcn Data Table 使用 |
| 表单 | vee-validate、zod |

开发时 Vite 将 `/api` 代理到 FastAPI。生产走现有 nginx，页面与接口同域。访问令牌只放内存。刷新令牌继续使用后端的 HttpOnly cookie。打开页面时先用 cookie 换令牌，换不到就进入登录页。顶栏「退出」先等待进行中的令牌刷新结束；仅当刷新后仍是同一账号时才 `POST /api/v1/auth/logout`，否则只清空本机会话并进入登录页。

## 4. 信息架构

登录页在鉴权之外。登录后的布局是左侧菜单、顶栏和内容区。菜单来自 `GET /api/v1/users/me/menus`。`component` 为 `Layout` 的节点是目录，其余字符串对应 `src/views/` 下的页面，例如 `asset/device/index`。`meta.hidden` 的路由照常注册，不出现在侧栏。找不到组件时注册失败，并显示「页面未实现」。

菜单可见只决定导航。接口仍由后端鉴权，按钮根据当前用户权限码显示。菜单保存成功后重新请求当前用户菜单并更新路由。

## 5. 分页

公开列表只使用一种交互和一种合同。底栏为：

`[起始行] - [结束行]  共 total 条  ‹ ›`

行号从 1 计，闭区间。默认 `1 - 20`。失焦或回车后，窗口长度变为 `结束行 - 起始行 + 1`。上一窗和下一窗按当前窗口长度平移；贴到第 1 行或最后一行时缩短窗口。起始大于结束、空值或非数字时，回到上一次有效区间。筛选变化时回到 `1 - 20`。`start` 和 `end` 写在地址栏里。当前窗口被删空且起始行大于 1 时，按当前窗口长度退一窗。`total` 变小导致结束行越界时，把结束行收到 `total`。

查询参数是 `start`、`end`，以及用户、设备、工作线和审计列表已有的 `filter` JSON。两个都省略时由服务端取第 1–20 行。响应为 `{items, total, start, end}`，`start` 和 `end` 回显请求值。窗口长度限于 1–100 行，偏移 `start - 1` 不超过 100000。前端在发出超限请求前停住，并保持原区间。

角色、权限和菜单接口返回全量，页面不做行号窗口。审计的当前日志和归档日志是两个标签，共用这一底栏。归档标签需要 `admin:audit:read_archive`。

前端不保留 `page` / `page_size` 或 `limit` / `cursor` 兼容层。后端落地前，测试使用符合上述响应的假数据。

## 6. 页面行为

### 6.1 工作线

筛选字段为工作线编码、名称、业务编码和区域名。

新建时先从 `GET /api/v1/businesses` 选择业务，再填写编码、名称、启用状态、区域、说明和排序。设备角色和位置可以先空着保存。业务声明中的必需角色未绑定时，表单标出「未完成」，仍然允许保存。

编辑提交当前可见字段和读取到的 `version`。

- 尚未选择业务时可以选一次。选定后业务编码只读，保存时可以重复提交原值。
- `is_enabled` 阻止该线新任务进入，不代替设备急停。
- 每个业务角色一个下拉框，选项只来自已经归到这条工作线的设备。同一台设备不能进入两个角色。
- 每个位置槽一个编码输入。
- 工作位额度整表替换。容量留空提交 `null`，表示不限额；填写时为 1 到 2147483647 的整数。交接口不配置货架额度。
- 清空全部角色或位置绑定前先确认。空对象会清空服务端绑定。

删除要求这条线已经没有设备，并提交 `version`。仍有设备或货架责任未结束时，展示服务端返回的说明。

### 6.2 设备

列表只显示配置：编码、名称、所属工作线、ECS 地址、排序。筛选字段为编码、名称、工作线和 ECS 地址。列表不请求设备状态，也不能在列表里修改设备编码或地址。

发现设备时输入 ECS 地址并预览。结果分为未登记、已登记和地址冲突，并显示过期时间。只能勾选未登记项，可选归入一条工作线后登记。

地址冲突进入换址。请求带当前版本、当前地址、本次预览令牌、原因，并要求勾选确认。

详情可改名称、说明和排序。拥有 `asset:device:refresh` 时，可手动刷新一次状态。结果只留在本次打开的详情里，不轮询，不写回列表。刷新失败时，已打开的配置仍然保留。

调整归属可以多选，每台设备带自己的 `version`。目标工作线为空表示移出分组。整批成功或整批失败。

删除带 `version`。设备仍绑在工作线角色上时，提示先解除绑定。删除只去掉当前配置，再次登记必须重新预览。

### 6.3 用户、角色、权限、菜单

用户可按用户名、邮箱、启用状态、创建时间和角色筛选。新建要求用户名、邮箱和密码，并可设置是否允许多处登录。详情里修改邮箱、启用状态和多处登录，重置密码，以及分配角色。停用、改密码和重置密码会使该用户已有会话失效。若操作会让系统里不再有人持有设置角色权限的能力，展示服务端说明并保持原状。

角色可以改名，并用权限列表勾选授权。勾选只能提交当前用户自己拥有的权限码。仍有用户的角色不能删除。权限页只查看和新建权限码。菜单用树新建、修改和删除，字段为父级、路径、组件字符串、标题、图标、排序、隐藏和权限码。删除菜单前先确认。

### 6.4 审计

可按用户、资源、资源编号、动作和时间筛选。拥有 `admin:audit:read_archive` 时，当前日志页提供一次归档操作，调用 `POST /api/v1/admin/maintenance/archive-audit`，并显示归档条数。

## 7. 保存与错误

工作线和设备编辑器持有最近一次读取到的 `version`。更新、删除、调整归属和换址都带上它。成功后用响应中的新版本替换本地值，并使对应列表和详情查询失效。

接口错误体为 `trace_id`、`code`、`message`、`detail`。页面展示 `message`；校验失败且存在 `detail` 时一并展示。

| 状态 | 行为 |
|---|---|
| 400 | 停在表单，展示服务端说明 |
| 401 | 用刷新 cookie 换一次令牌并重试原请求；同一时刻只刷新一次，其余请求等待结果。仍失败则清空会话并进入登录页 |
| 403 | 保留当前页，提示没有权限 |
| 404 | 关闭编辑器并刷新列表 |
| 409 | 展示服务端说明，重新读取服务器记录，保留用户已改内容。不自动覆盖，不自动重试 |
| 429 | 按 `Retry-After` 提示稍后再试，不自动连发 |
| 502、503、504 | 保留已打开的配置，提示暂时不可用 |

预览返回 `PREVIEW_EXPIRED` 或 `PREVIEW_CHANGED` 时，清掉本次预览令牌，要求重新拉取。

## 8. 前端结构与数据流

```text
src/
  app/            启动、路由、QueryClient、Pinia
  api/            统一客户端、错误类型、按资源分的请求函数
  auth/           内存令牌、登录、刷新、退出
  menus/          把菜单响应编成路由
  components/     shadcn 组件、行号分页、表格、带版本号的表单壳
  views/asset/device
  views/asset/workline
  views/system/user
  views/system/role
  views/system/permission
  views/system/menu
  views/system/audit-log
```

Pinia 不存放列表和详情。TanStack Query 的键包含资源名、`start`、`end` 和筛选。行号分页组件只向外提供下一次的 `start` 和 `end`。客户端为请求附上内存中的访问令牌。

实现顺序固定为：工程骨架与登录菜单、行号分页与列表壳、工作线、设备、用户与授权及菜单、审计。

## 9. 测试

使用 Vitest 和假的接口客户端，本轮不把浏览器联调当作完成条件。覆盖：

- 行号窗口的默认值、手输区间、贴边缩短，以及超长窗口和超限偏移时不发请求。
- 客户端附带令牌；`401` 后只刷新一次；刷新失败进入登录页。
- 退出等待进行中的刷新；同一账号才请求 `logout`，换人后只清本地会话。
- 菜单目录、隐藏页和未知组件。
- 工作线已选业务只读；清空绑定前需要确认。
- 设备只能登记预览中的未登记项；换址必须填写原因并确认。
- `409` 后重新读取，表单中的未保存修改仍然保留。

## 10. 非目标

- 不实现对接历史页面和 ECS 调试台。
- 不在前端换算或兼容旧的 `page` / `page_size` 与 `limit` / `cursor`。
- 不轮询设备状态，不把状态写入列表。
- 不修改 `maintenance-admin`。分页合同由该仓库的 issue #137 跟踪。
